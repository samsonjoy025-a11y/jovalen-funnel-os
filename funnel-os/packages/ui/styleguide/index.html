Phase 1 · Design System

Build your funnel. Connect your marketing. Find what's limiting growth. Keep improving.

Every screen in Phases 4–13 of the implementation plan is assembled from what follows. If a product screen needs something that is not on this page, the design system is amended first — in its own reviewed PR — and the feature waits. That is the rule, and it is what stops this becoming forty bespoke tables.

Three layers, one source

packages/tokens/src/*.json (W3C DTCG) is the single source. The build emits CSS custom properties, a resolved JSON object, and a typed TS module. Components may reference semantic tokens only. Primitive tokens are never referenced by a component; a lint rule fails the build if one is.

Every value is checked, not reviewed

The build validates every declared foreground/background pair against WCAG 2.2 AA in both themes and exits non-zero on a new failure. 32 declared pairs, 64 checks. Contrast is a build gate, not a design review comment.

The PRD is encoded here, not just referenced

§87's five content states are one primitive. §60's fact/analysis/hypothesis/recommendation distinction is one component. §104's planned-versus-measured guarantee is one badge. §86's textual chart summaries are built into the chart frame. These are product requirements that happen to have a visual form, so they live in the design system.

Foundations

Governance

How this stays a system instead of a suggestion.

A7 — token discipline

No component may define a colour, spacing value, radius, or duration outside the token set. Enforced by styling lint plus visual regression.

Contrast gate

Every readable pair is declared in the build and checked in both themes at build time. A new failing pair fails the build.

Rule 1 — design-first

A feature phase that needs a new pattern or chart type amends the design system first, in its own PR, and waits for it.

Lifecycle (ADR 0022)

Semver on the package. Any change to a component's rendered output requires visual-regression review. Deprecations ship with a codemod, never a silent break.

§24 blocks

Safety

The published-page runtime may only use the declared token subset. A tenant-authored page cannot escape the brand, contrast, or type envelope — the block schema is validated, not freeform HTML.

§25 · §63

AI fills the blocks from business context and may not invent testimonials, statistics, certifications, awards, guarantees, or claims. Anything unconfirmed renders as a ConfirmRequired placeholder that blocks publish.

Quality

Accessibility

§86 targets WCAG 2.2 AA. None of this is a Phase 13 audit item, because none of it can be retrofitted onto forty hand-built tables.

Contrast is a build gate

32 declared pairs × 2 themes, checked at build time. A new failing pair fails the build rather than a review.

Focus is a token

Every interactive element gets the same focus-visible ring, drawn from --ds-focus-*. Removing it is visible in review.

Colour is never the only signal

Deltas carry an arrow and a sign. States carry a glyph and a word. Severity carries a text label. Series colours pair with legend labels and a table.

Targets are at least 24px

Small badges are excluded because they are not interactive. Every control and table row meets the minimum.

Charts have text equivalents

A written summary and a data table, always reachable. The SVG has a descriptive aria-label in words, not numbers alone.

Reduced motion honoured

All animation collapses under prefers-reduced-motion. Nothing conveys information through motion alone.

Errors are announced

Field errors are linked with aria-describedby and the input carries aria-invalid. Live regions for sync and publish status.

Published pages too

The landing runtime is held to the same standard. A customer's page that fails AA is a defect in this product.
